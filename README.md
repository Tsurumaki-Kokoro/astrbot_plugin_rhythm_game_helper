# AstrBot 音游助手

v0.4.0：本地音游知识检索、AI 工具、收录审核及 IIDX 知识库分流，兼容 Chat Plus 聊天请求。
检索本身无额外依赖，不调用向量模型；自然语言回复由当前聊天模型完成。

## 使用

以下示例的 `/` 是命令前缀，请换成当前会话配置的前缀。已配置“薄绿”前缀的会话也可发送 `薄绿音游查询 定数`。

| 指令 | 功能 |
| --- | --- |
| `/音游助手` | 版本、词条数、资料加载错误数和帮助 |
| `/音游查询 定数` | 查询标题、别名及关键词，最多返回 3 条 |
| `/音游查询 叠键和切换有什么区别` | 支持自然语言及带空格的查询 |
| `/音游查询 Malody 判定窗口` | 查询游戏相关资料 |
| `/音游目录` | 分页显示所有词条，每页 12 条 |
| `/音游目录 2` | 第二页 |
| `/音游目录 Malody 2` | 筛选标题、别名或分类后查看第二页 |
| `/音游收录 标题 \| 摘要 \| 可选详情 \| 可选分类` | 普通用户提交待审核；AstrBot 管理员直接收录 |
| `/音游待审 1` | 管理员分页查看待审列表 |
| `/音游审阅 编号` | 管理员查看单条待审内容 |
| `/音游审核 编号 通过` | 管理员批准，拒绝时将“通过”换成“拒绝” |

查询内容限制 200 字。长条目截断显示，并保留出处、资料文件和存疑提示。
未命中时明确返回未找到，不生成额外答案。命中结果仅是相关资料，不保证是最新版本。

## 资料与检索

`kb/*.json` 来自用户提供的 `skills-rhythm-kb.zip`，原样保留，共 711 条有效词条。
读取时按标题忽略大小写去重，保留第一条。原始 `source` 与来源文件分别保存。
支持 UTF-8 BOM、数组或 `entries` 对象格式；坏文件会记录警告，状态指令显示错误数。
没有有效资料时插件初始化报错，避免空库伪装为正常工作。

检索移植原包的标题/别名加权、中文滑窗、二字组与 IDF 降权，完整名称匹配优先。
JSON 文件新增、修改或删除后，在下次查询时重新载入，无需重启。
仅更新已绑定词条的内容；本阶段没有聊天写入功能。

## AI 工具与 Chat Plus

| 工具 | 参数 | 功能 |
| --- | --- | --- |
| `rhythm_search_knowledge` | `query`，`limit=3`（最多 5） | 关键词检索，返回有界 JSON 资料、来源、存疑和截断标记 |
| `rhythm_list_knowledge` | `keyword=""`，`page=1` | 分页目录，每页最多 12 条 |
| `rhythm_submit_knowledge` | `title`、`summary`、可选 `details`、`category` | 用户明确要求时提交，权限由真实事件判断，模型不能指定管理员身份 |

需要当前模型支持工具调用，并在当前人格的工具设置中允许这两个工具。
插件使用 AstrBot 原生 `llm_tool` 注册，不额外向请求塞入被人格禁用的工具。
工具结果返回给模型，不直接向群聊发送；回复和表情继续由现有聊天流程处理。

请求钩子优先级为 -100，晚于当前 Chat Plus 的 -1：等 Chat Plus 完成上下文与工具列表重建后，
仅在当前消息包含音游相关线索且查询工具可用时附加简短规则，重复执行不重复注入。
规则要求知识问答先查、无依据不编造、保留存疑和版本限定，沿用现有人格语气。
默认 2～3 句、约 120 字以内，不使用标题/加粗/项目列表和重复总结；用户明确要求详细回答时再展开。
不读写人格，不改变已有 prompt、contexts 和工具列表，不将群友说法自动写入资料。
没有音游线索时不额外注入；即使未触发线索检测，模型仍可按工具描述自行检索。

联动流程：Chat Plus 判断回复 → LivingMemory 召回 → Chat Plus 重建请求 → 本插件附加规则 →
模型查询资料并生成最终回答 → 原有消息装饰与表情发送。
规则注入不强制每次模型必定调用，当前没有自动预检，也不会将工具错误静默替换为猜测。
工具不可用时不注入规则；可通过查询指令检查本地资料。

验证示例（在已开启 AI 回复的会话发自然语言）：
- “薄绿，叠键和切换有什么区别？”应先调用 `rhythm_search_knowledge` 再简短解释。
- “薄绿，音游知识库有哪些 Malody 的资料？”可调用 `rhythm_list_knowledge`。
- “薄绿，今天天气不错。”不应触发本插件的规则注入或额外检索。
- 查不到的音游问题应明确说本地资料未覆盖，不能声称已查询到事实。

## IIDX 知识库分工

现有原生知识库 `Beatmania IIDX Singal Player` 的 SP11/SP12 资料仍由 `astr_kb_search` 查询。
IIDX/beatmania、SP11/SP12、CPI/BPI 和专项谱面练习优先走原生工具；通用术语与其他游戏走本地工具。
规则只引用本轮实际可用的原生工具，不添加/删除其他工具，不改动原生库文档、索引、配置。
本地查询工具检测到 IIDX 专项问题时返回 `routed=true` 和原生工具名称，而非“库中无资料”。
直接“音游查询 IIDX …”会解释分工。本插件拒绝将 IIDX 专项资料重复收录，须由管理员更新原库文档。
未明确游戏的歌名/术语可能有歧义，应补充游戏名；跨游戏问题需要按游戏分别查证。

## 收录与审核

用户明确说“收录/记一下”等时可调用收录工具，或使用收录指令。只依据当前请求明确提供的内容提交。
以 AstrBot 配置的管理员身份（`event.is_admin()`）判断，QQ群管理员不自动获得此权限。
普通用户提交 `pending`，审核前不可被检索；管理员提交为 `approved`，立即可检索。
待审列表及完整详情只允许 AstrBot 管理员查看。只有审核指令能批准/拒绝，未注册 AI 审核工具。
重复标题或与现有别名冲突会拒绝，原始 JSON 永不覆盖。群友补充单独标注，并非官方来源。

持久化目录：`data/plugin_data/astrbot_plugin_rhythm_game_helper/knowledge.sqlite3`。
数据库保留提交人、会话、审核人和审核状态，事务和唯一索引防止重复写入。
每次变更前生成 SQLite 快照，`backups/` 保留最近 20 份；重载/重启后资料仍在。
最多保留 1500 条待审/已通过补充，每位普通用户最多同时 20 条待审。
标题最多 100 字，摘要 500 字，详情 3000 字，分类 60 字。

## 开发与验证

需要 AstrBot >= 4.29.1，使用其 Python 环境，无需安装额外依赖。

```sh
python -m unittest discover -s tests -v
python -m py_compile main.py knowledge.py presentation.py chat.py store.py submissions.py
```

修改后通过 AstrBot 插件管理重载本插件。`kb` 内的资料更新可在下次指令执行时自动读入。
完整的原生工具注册与指令测试需要在 AstrBot 的 Python 环境运行；普通 Python 会跳过这部分测试。
